## 1. 구현 순서

`git log`로 확인되는 실제 작업 순서는 README가 추천한 순서(`진행 순서 추천`)와 거의 동일합니다.

1. **DTO** — `naver_stock_dtos.dart`의 `fromJson` / 숫자·날짜 파싱부터 구현해 `naver_stock_dtos_test.dart`를 먼저 통과시켰습니다.
2. **Client** — `naver_domestic_stock_client.dart`의 검색/실시간/메타데이터/일별시세 HTML 파싱을 구현했습니다.
3. **Repository** — `naver_watchlist_repository.dart`에서 client가 반환한 DTO를 앱 모델(`WatchlistItem`, `WatchlistDetail` 등)로 변환하고, 캐시/배치/병렬 처리를 붙였습니다.
4. **View & Controller** —  `search_result_row.dart`, `search_toast.dart`, `watchlist_date_bottom_sheet.dart` 를 Figma 기준으로 맞추고 `search_controller.dart`, `watchlist_screen.dart` 상태 동기화를 연결했습니다.
5. **마무리(`finish`)** — 토스트/검색 컨트롤러 디테일을 다듬고 골든/데모로 최종 확인했습니다.
6. **점검 및 보완** — 위 5단계 이후 코드를 다시 훑으면서 발견한 문제들을 고쳤습니다.
   - `_metadataCache`가 실패 fallback까지 영구 캐싱하던 것을 성공/실패를 구분해 캐싱하도록 수정(`_MetadataCacheEntry`, TTL 30초)
   - `_runInBatches` 두 곳에 하드코딩돼 있던 배치 크기(`4`)를 `dailyHistoryFetchBatchSize` 하나로 통일
   - `fetchRealtimeQuotes`에서 quote 하나 파싱 실패가 배치 전체를 죽이던 것을 개별 격리로 수정(`_parseRealtimeQuoteItem`)
   - `SearchController.setQuery`에 200ms debounce 적용
   - `search_screen.dart`/`watchlist_screen.dart`의 mounted 체크 누락·위치 오류 4곳 수정
   - 하트 버튼 더블탭 방지(`_pendingFavoriteToggles`)
   - 골든 테스트 6개를 이 환경 기준으로 재생성

## 2. 어떤 가정을 두었는지

가장 핵심 가정은 다음과 같습니다.

> Naver도 어쨌든 **외부 API**이므로 네트워크 실패·응답 지연 자체에 대한 방어는 유지한다.
> 다만 국내 주식 시세 데이터셋(종가/시가/고가/저가/거래량 등)은 오랫동안 정형화되어 있어, **필드 구성 자체(스키마 모양)는 안정적**이라고 가정하고 타협했다.

즉, 두 종류의 방어를 구분했습니다.

- **유지한 방어**: 네트워크 실패, 타임아웃, 개별 row 파싱 실패 같은 "호출이 실패할 수 있다"는 전제의 방어. (`try/catch` + fallback + `debugPrint`, 개별 row 스킵 등)
- **하지 않은 방어**: "Naver가 필드 이름을 바꾸거나 스키마 자체를 변경할 수 있다"는 전제의 방어. 여러 스키마 버전을 동시에 지원하거나, 필드 유무에 따라 분기하는 코드는 만들지 않았습니다.

그리고, 레포에 있는 골든 테스트 기준 이미지와 실제 구현되어있는 `검색 결과 없습니다` 페이지의 경우 기준이미지가 달라, 피그마와 프로젝트에 구현된 내용에 맞춰 골든 테스트를 진행하기로 했습니다.
